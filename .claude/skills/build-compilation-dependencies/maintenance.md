| `.github/workflows/check-package.yml`                                         | Per-package job: reads `name` + `ci.tools` from the package's `package.json`, filtered install, builds the package and its workspace deps, runs `check` then `test` (`TEST_ALL`). `check` never builds: a build rewrites `lib/` while dependents read it                                                                                                                                                       |
| `.github/actions/setup-env/action.yml`                                        | pnpm + Node + install; pinned tool versions (cmake, ktlint, clang-format and clang-tidy from LLVM 23, llvm, diff-cover); `CC`/`CXX=clang` with cmake; the clangd build-directory cache (keyed by `directory`) with clang-tidy                                                                                                                                                                                  |
| `.github/workflows/ci.yml`                                                    | The only PR entry workflow; skips drafts, `ready_for_review` is listed (not a default type). One `changes` job owns every path filter (YAML anchors: a package's filter includes its workspace deps', `toolchain`/`shared` lists are reused); one `check-package` job per package; `native-build.yml` and `wpt-tests.yml` called on pull requests and manual runs; `cpp-coverage.yml` on pull requests; `gate` |
| `.github/workflows/pr-report-comment.yml`, `.github/actions/upload-pr-report` | Jobs upload `<kind>/report.md` folders as `pr-report-<name>` (skipped when empty); the `workflow_run` on CI finds the open PR by head owner + branch (fork-safe) and keeps one comment per kind, marker `<!-- pr-report:<kind> -->`                                                                                                                                                                            |
| `.github/workflows/native-build.yml`, `wpt-tests.yml`, `cpp-coverage.yml`     | Called by `ci.yml` only (`workflow_call`); no own triggers, path filters or draft guards. The WPT base side keeps inline setup steps (it checks out the base branch)                                                                                                                                                                                                                                           |
