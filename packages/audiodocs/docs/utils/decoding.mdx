# Decoding

You can decode audio data independently, without creating an [`AudioContext`](../core/audio-context.mdx), using the exported functions [`decodeAudioData`](./decoding.mdx#decodeaudiodata),
[`decodePCMInBase64`](./decoding.mdx#decodepcminbase64), [`getAudioDuration`](./decoding.mdx#getaudioduration), and [`openAudioDecodeStream`](./decoding.mdx#openaudiodecodestream).

If you already have an audio context, you can decode audio data directly using its [`decodeAudioData`](../core/base-audio-context.mdx#decodeaudiodata) function;
the decoded audio will then be automatically resampled to match the context's `sampleRate`.

:::caution
Supported file formats:
- flac
- mp3
- ogg
- opus
- wav
- aac
- m4a
- mp4
- aif
- aiff
- caf (ios)
:::

### `getAudioDuration`

Reads the duration of an audio source without decoding the full file into an [`AudioBuffer`](../sources/audio-buffer.mdx).
Use this when you only need the encoded file duration. Use [`decodeAudioData`](./decoding.mdx#decodeaudiodata) when you need sample data for playback or processing.

On mobile, duration is read from file metadata via the native decoder. Local paths, `file://` URIs, remote `http(s):` URLs, and `ArrayBuffer` input are supported.
Remote URL probing requires FFmpeg in the native build, which is off by default — see [Build-time flags](../other/build-time-flags.mdx#enableffmpeg).
Asset module ids, base64 data URLs, and blob URLs are rejected explicitly.

On web, this API uses browser audio metadata loading and supports sources the browser can load, such as remote URLs, relative URLs, blob URLs, and data URLs.

There is no `sampleRate` option because the returned duration belongs to the encoded source and does not depend on a caller-selected output sample rate.

Throws an error when duration metadata is unavailable or when the input type is not supported.

### `decodePCMInBase64`

Decodes base64-encoded PCM audio data.

| Parameter | Type | Description |
| :---: | :---: | :---- |
| `base64String` | `string` | Base64-encoded PCM audio data. |
| `inputSampleRate` | `number` | Sample rate of the input PCM data. |
| `inputChannelCount` | `number` | Number of channels in the input PCM data. |
| `isInterleaved` <Optional />| `boolean` | Whether the PCM data is interleaved. Defaults to `true`. |

#### Returns `Promise<AudioBuffer>`


<details>
<summary>Example decoding with data in base64 format </summary>
```tsx
const data = ... // data encoded in base64 string
// data is interleaved (Channel1, Channel2, Channel1, Channel2, ...)
const buffer = await decodeAudioData(data, 4800, 2, true);
```
</details>

### `openAudioDecodeStream`

Opens an audio source to decode it a few frames at a time, instead of as one [`AudioBuffer`](../sources/audio-buffer.mdx).

[`decodeAudioData`](./decoding.mdx#decodeaudiodata) returns the whole source as decoded samples, so its memory follows the duration of the audio:
about 21 MB per minute of stereo sound at 44.1 kHz, whatever the size of the file. A stream only holds the chunk being read.
Use it for work that goes through the audio once — waveforms, spectra, loudness, beat detection, speech recognition — on sources too long to hold decoded.

| Parameter | Type | Description |
| :---: | :---: | :---- |
| `input` | `ArrayBuffer` \| `string` \| `number` | The inputs [`decodeAudioData`](./decoding.mdx#decodeaudiodata) takes: encoded audio bytes, a local path or `file://` URI, a remote URL, or an asset module id. |
| `options` <Optional /> | [`AudioDecodeStreamOptions`](./decoding.mdx#audiodecodestreamoptions) | Output sample rate and download options. |

#### Returns `Promise<AudioDecodeStream>`

Rejects when the source cannot be opened, with the errors [`decodeAudioData`](./decoding.mdx#decodeaudiodata) rejects with.

:::info
A remote source is downloaded before it is opened, and encoded bytes are kept in memory while the stream is open.
That is the size of the file, not of its decoded audio. To keep memory lowest, open a local file.
:::

#### `AudioDecodeStreamOptions`

| Parameter | Type | Default | Description |
| :---: | :---: | :---: | :---- |
| `sampleRate` <Optional /> | `number` | sample rate of the source | Sample rate of the decoded audio, in Hz. |
| `fetchOptions` <Optional /> | `[RequestInit](https://github.com/facebook/react-native/blob/ac06f3bdc76a9fd7c65ab899e82bff5cad9b94b6/packages/react-native/src/types/globals.d.ts#L265)` | — | Additional fetch options when `input` is a remote URL (for example, auth headers). |

<details>
<summary>Example computing a waveform without holding the decoded file</summary>
```tsx
import { openAudioDecodeStream } from 'react-native-audio-api';

const stream = await openAudioDecodeStream('file:///tmp/set.mp3', {
  sampleRate: 22050,
});

const peaks: number[] = [];
try {
  let chunk = await stream.read(4096);
  while (chunk !== null) {
    const samples = chunk.getChannelData(0);
    let peak = 0;
    for (let i = 0; i < samples.length; i += 1) {
      peak = Math.max(peak, Math.abs(samples[i]));
    }
    peaks.push(peak);
    chunk = await stream.read(4096);
  }
} finally {
  stream.close();
}
```
</details>

## `AudioDecodeStream`

Returned by [`openAudioDecodeStream`](./decoding.mdx#openaudiodecodestream).

### Properties

| Name | Type | Description |
| :----: | :----: | :-------- |
| `sampleRate` <ReadOnly /> | `number` | Sample rate of the decoded audio, in Hz: the requested one, or the one of the source. |
| `numberOfChannels` <ReadOnly /> | `number` | Number of channels of the decoded audio. |
| `duration` <ReadOnly /> | `number` | Duration reported by the source, in seconds; `0` when it is unknown. |

### Methods

#### `read`

Decodes the next frames of the source. Each read continues where the previous one stopped, and reads run one at a time, in the order they were requested.
Await each read before requesting the next: reads queue behind one another, and requesting dozens at once blocks the JS thread until the decoder catches up.

The chunks of a stream, put end to end, hold exactly the samples [`decodeAudioData`](./decoding.mdx#decodeaudiodata) returns for the same source and sample rate, whatever the chunk size.

| Parameter | Type | Description |
| :---: | :---: | :---- |
| `frameCount` | `number` | Number of frames to decode. A positive integer. A few thousand frames is a good chunk; a value larger than what is left returns what is left. |

##### Returns `Promise<AudioBuffer | null>`

An [`AudioBuffer`](../sources/audio-buffer.mdx) of `frameCount` frames, shorter only when the source ends inside it, and `null` once the source has ended.

A source the decoder fails on midway also ends with `null`, as [`decodeAudioData`](./decoding.mdx#decodeaudiodata) returns what was decoded before the failure.
Compare the frames read with `duration * sampleRate` to tell a truncated source from a complete one.

##### Errors

| Error type | Description |
| :---: | :---- |
| `RangeError` | `frameCount` is not a positive integer. |

#### `seek`

Moves the read position.

| Parameter | Type | Description |
| :---: | :---: | :---- |
| `seconds` | `number` | Position to read from, in seconds. |

##### Returns `Promise<void>`

##### Errors

| Error type | Description |
| :---: | :---- |
| `RangeError` | `seconds` is negative or not finite. |

:::caution
The next read starts where the decoder can resume, which depends on the format and on the platform: exactly at `seconds` for PCM, and at a nearby position for compressed formats, which can be noticeably earlier or later.
Only sequential reads are sample-exact: to read the same audio twice, prefer reading from the start again (`seek(0)`) over seeking into the middle.
Seek within the duration of the source; what a position past its end reads is not specified.
:::

#### `close`

Releases the decoder once the reads already requested have settled. Reads and seeks requested afterwards reject.
An open stream holds a decoder and a thread of its own: close it as soon as you are done with it. A stream that is never closed is only released when it is garbage collected.

##### Returns `undefined`

### Remarks

#### Web

A browser only decodes a source as a whole. On web, `openAudioDecodeStream` decodes the source with the browser's `decodeAudioData` and the stream hands out slices of the result:
the API is the same, the memory saving is not.
